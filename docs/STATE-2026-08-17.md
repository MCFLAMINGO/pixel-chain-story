# State, 17 August 2026

Written at the end of a soundness pass so the reasoning survives the session that had
it. **Read this and [`STATE-2026-08-13.md`](./STATE-2026-08-13.md) before starting
work.** The 13 August priorities still stand where this file does not supersede them.

## What this session was

Two external reads of the repository arrived — one an LLM summary of the public site,
one a careful 6-page read of the code at `193107d` against live chain and contract
state. Both were substantially right, and both were more complimentary about the
engineering than about the surface area around it. The instruction was to answer the
criticism, close the loose ends, and make the thing sound before inviting a second
operator.

That last clause is the one that shaped everything. **Soundness became a gate rather
than a phase**: no second operator, and no gossip port exposed to the internet, until
a numbered list of conditions is green.

## The finding that reordered the work

The audit assumed the sequencer registry was a permission system. It was not — it was a
cache the attacker populates.

`node.ts` admitted a block's _claimed_ producer into the local registry **before**
validating the block ("learn producer before accept"), and `acceptBlock` then checked
the block's electable set against the registry the block had just poisoned. Grinding one
keypair until it won the lottery was enough. A proof of concept did it in half a second:
an address that was never registered, invited or staked extended the tip, minted 50 PIX,
became permanently electable, and `verifyChain` returned `true` afterwards.

The audit called the related sequence-grinding bug "theoretical with one sequencer". It
was worse than theoretical, because the roadmap's number-one item — add a second
sequencer — is precisely the act that exposes the gossip port.

## The finding that was live on the public node

`POST /tx` was public, zod shape-checked only, then appended to `pending`, gossiped and
persisted with no signature check, no ownership check, no cap and no rate limit.
`pending` is part of `serializeChain`, so every submission rewrote it to the one Railway
volume holding the only copy of history.

Measured end to end, 300 unauthenticated `curl`s with unique txids:

|            | before              | after               |
| ---------- | ------------------- | ------------------- |
| HTTP       | 300 × 200           | 46 × 400, 254 × 429 |
| tip        | 0 → **300**         | 0                   |
| datadir    | 32 KB → **6.33 MB** | byte-identical      |
| PIX minted | **15,050**          | 50 (genesis only)   |

The emission is the part that matters. Junk made `pending` non-empty, which made
`trySequence()` produce a block, which minted the light reward. Fifty PIX and twenty-one
kilobytes of permanent history per `curl`, from anyone, with no key. This was never only
a denial of service; it was unauthenticated remote control of block production.

## The finding nobody wanted

**`verifyChain` rejected the crowned chain.** Pixels 0–12 failed; 13–46 passed.

Commit `c8d5d54` (PIX-10/PIX-16) changed three things at once, each of them a genuine
improvement: ML-DSA domain separation moved into the FIPS-204 `ctx` parameter, the OTS
signed digest widened 128 → 256 bits, and OTS payloads gained a length-prefixed domain
tag. Together they shipped with no migration, so every signature made before them could
not verify under the rules that replaced them.

Nothing caught it for weeks because nothing re-verifies stored history: `deserializeChain`
never calls `verifyChain`, and `acceptBlock` only ever sees blocks that do not exist yet.
**A verifier that is never pointed at the past cannot report that the past has stopped
verifying.**

No coin was ever at risk and no history was lost. What was false is the project's best
claim — that anyone can hold 1.4 MB and check the whole picture. Until 16 August they
could not get past pixel 0.

The fix is a bounded, height-gated legacy verification era (`sig-era.ts`): below pixel 13
on network 20553 the old constructions verify, everywhere else the current ones do,
exactly one era per height, never a fallback — because a fallback is a downgrade oracle.

## What is true now that was not

Twelve tasks, each with tests that failed before the change. The full list is in the
commit history; the ones that change what you can say out loud:

- **Membership is a fold over chain history**, not gossip state. A stranger cannot
  produce. Two nodes with opposite gossip histories reach the same verdict on the same
  block, so the drift `electable-drift-selftest.ts` was written to demonstrate is now
  unrepresentable rather than merely fixed.
- **The mempool has a door.** Signature and ownership checked before anything is stored,
  relayed or persisted; bounds on blocks, metadata, frames and pages; rate limits on
  writes and none on reads, because a stranger verifying the chain without permission is
  the property this project exists to have.
- **The gossip wire is validated** to the same standard as HTTP. Seven hostile frames
  over a real socket — garbage bytes, unknown types, a 9 MB frame, a hello carrying 5,000
  sequencers — all dropped with named reasons, node unharmed.
- **Transaction identity is bound to content**, sequence progression is bound, and the
  arrays a block carries (`field`, `wave`) are compared rather than only their digests.
  That last one makes "the picture partly _is_ the chain" true of the bytes a node
  serves, not only of the commitments.
- **Fees are not issuance.** The first nonzero fee would have made `verifyChain` reject a
  valid chain.
- **The node key can be sealed at rest**, with the same AES-GCM-256 / PBKDF2-210k the
  phone wallet has always used. Plaintext still loads — a security change that strands
  the operator it protects gets reverted — but the node says which mode it is in at every
  start and in `/health`.
- **Accept and replay agree as a property**, over 25 mutations across random histories.

## The method changed, and that matters more than any single fix

Each pass over this codebase found more bugs than the last. That is not a method, and a
plan built that way can never say a thing is sound — only that nobody has looked
recently.

So four registries now fail the build rather than relying on anyone's diligence:

| Guard                   | Fails when                                                                                                                                                                   |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `test:coverage-harness` | a consensus type grows a field nothing binds; a write route is unthrottled; a gossip message has no schema — and mutation-tests all 46 fields to prove the bindings are real |
| `test:claims-guard`     | any file states a supply schedule the code does not implement                                                                                                                |
| `test:spec-conformance` | `SPEC.md` and the code disagree about any of 16 constants, in either direction                                                                                               |
| `test:audit-scope`      | a module is unclassified, or a consensus module imports a model                                                                                                              |
| `test:crowned-replay`   | real history stops verifying                                                                                                                                                 |

Every one was validated by breaking the code on purpose and watching it fail. A guard
nobody has watched fire is a guard nobody should trust.

## What is still not true

Unchanged from 13 August, and not addressed by this session:

- **One sequencer, zero peers.** No liveness, no censorship resistance, no finality.
  Still a succession problem rather than a consensus one — but the succession is now
  _possible_, which it demonstrably was not before.
- **One volume, one key, one human.** `pixel backup` works and is tested; "done" still
  means the code path works, not that a second person is holding a copy. This remains
  priority #1 from the previous state note.
- **Fork choice is depth-1.** Two honest nodes partitioned for two pixels cannot
  converge. This blocks multi-operator as surely as membership did, and is the next
  structural piece.
- **No finality rule.** Nothing can be pointed at and called irreversible. The anchors on
  Sepolia and robinhood-testnet are the obvious foundation for one.
- **The leader is predictable.** `sha512(pols-lottery|prevHash|sequence|address)` over
  public inputs, so the next producer is known and can be targeted. Matters only with
  more than one operator; fixing it is a hard fork and belongs on a fresh devnet id.
- **No external audit.** `docs/AUDIT.md` stays PREPARING until a report link exists.

## What to do next, in order

1. **Get the datadir and key into a second person's hands.** Still the highest-value act
   available, still not a code change.
2. **Real fork choice over a block tree**, then a finality rule anchored to the public
   venues. Both are prerequisites for a second operator that helps rather than diverges.
3. **Two operators, proven by killing one** — boot two nodes on a fresh network id, kill
   the elected producer, and show the other takes over and both converge afterwards.
4. **Test vectors** (`fixtures/vectors/`), so a second implementation is possible. That
   is what "robust like Ethereum" actually rests on, and every constant pinned in
   `SPEC.md` §2.1 is one fewer thing a second client has to guess.

## The sentence to keep

From the previous state note, still the governing requirement:

> "I need to be able to walk away and it works."

Still not true. But the reasons are now four named structural gaps rather than an
unbounded list, and none of them is "somebody might find something."
